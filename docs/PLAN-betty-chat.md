# בטי — צ'אט בטיחות | אפיון ותוכנית (טיוטה לאישור)

> סטטוס: **טיוטה — ממתין לאישור לפני כתיבת קוד.**
> סעיפים המסומנים ❓ תלויים בתשובות לשאלות הפתוחות (סעיף 11).

## 1. מטרה וערך

בטי היא דמות של יחידת הבטיחות שעונה בכתב, בעברית, לשאלות בטיחות — בטון חם, קצר וברור.
הערך: מענה מיידי לשאלות נפוצות, הפניה נכונה לגורם אנושי, והנגשת נהלי בטיחות.

**מה בטי אינה:** היא אינה מחליפה ממונה בטיחות, אינה מאשרת עבודות, ואינה מוקד חירום.

## 2. הנחות עבודה

- קהל: סטודנטים, סגל ועובדי מעבדות ❓
- שפה: עברית (RTL) בלבד ב-MVP ❓
- בטי עונה **רק** מתוך מקורות שסופקו לה (נהלים רשמיים) ❓ — ולא מ"ידע כללי".
- אין התחברות משתמשים ב-MVP; שיחות אינן נשמרות בשרת.
- שימוש בשם ובלוגו של יחידת הבטיחות בטכניון דורש הרשאה רשמית ❓

## 3. MVP

1. מסך צ'אט אחד עם תמונת בטי, הודעת פתיחה והצעות לשאלות נפוצות.
2. תשובות בסטרימינג, עם ציון המקור (שם הנוהל / סעיף) בכל תשובה.
3. זיהוי מצב חירום (שריפה, פציעה, דליפה, חשיפה לחומר) → כרטיס קבוע עם מספרי חירום, לפני כל טקסט אחר.
4. "לא יודעת" מפורש כשאין מקור + הפניה לאיש קשר ביחידה.
5. סירוב מנומס לנושאים שאינם בטיחות.

מחוץ ל-MVP: קול/וידאו, היסטוריית שיחות, התחברות, לוח ניהול, שפות נוספות, דיווח תקלות/מפגעים.

## 4. User Stories

- כסטודנט במעבדה, אני שואל "איזה כפפות צריך לעבודה עם אצטון?" ומקבל תשובה קצרה עם מקור.
- כעובד, אני כותב "נשפכה לי חומצה על היד" ומקבל מיד הנחיית חירום ומספר טלפון.
- כמשתמש, כשבטי לא יודעת — היא אומרת זאת ומפנה לאדם.
- כמשתמש בקורא מסך, אני מנווט בצ'אט במקלדת ושומע כל תשובה חדשה.
- כממונה בטיחות, אני יודע בדיוק מאילו מסמכים בטי עונה.

## 5. מסכים וזרימות

## 6. ארכיטקטורה — שתי חלופות ❓

### חלופה א' — אב-טיפוס בתוך Claude (Artifact)
- מה: דף צ'אט שמפעיל את Claude דרך החשבון של הצופה.
- יתרון: מוכן מהר, אין שרת, אין מפתחות API.
- מגבלה: כל משתמש צריך חשבון Claude; לא מתאים להטמעה באתר היחידה; שליטה מוגבלת בלוגים ובמכסות.
- מתאים ל: הדגמה פנימית ואישור הקונספט.

### חלופה ב' — אפליקציית Web עצמאית (מומלץ לפרודקשן)
- Next.js (App Router) + TypeScript; קליינט RTL.
- Route Handler בצד השרת קורא ל-Claude API (מפתח ב-env בלבד), עם סטרימינג.
- ידע: קובצי Markdown של הנהלים בריפו ← נטענים ל-system prompt עם prompt caching. (אם הנפח גדל — מעבר לאחזור/RAG בשלב מאוחר.)
- אין DB ב-MVP.
- חלופות: שרת Node/Express נפרד (יותר תחזוקה); RAG מלא מההתחלה (מוקדם מדי).

```
Browser (RTL chat UI) ──POST /api/chat──▶ Next.js server ──▶ Claude API
                                             │
                                  knowledge/*.md (נהלים מאושרים)
```

## 7. API (חלופה ב')

## 9. אבטחה, פרטיות, נגישות

### Threat Model קצר
| איום | סיכון | בקרה |
|---|---|---|
| עצת בטיחות שגויה ("הזיה") | **גבוה** | מענה רק ממקורות מאושרים, ציון מקור, "לא יודעת", הבהרה קבועה, בדיקת תשובות ע"י ממונה לפני עלייה |
| Prompt Injection / חריגה מהנושא | בינוני | system prompt נעול, אין כלים/פעולות, סירוב לנושאים זרים |
| ניצול ה-API (עלות, ספאם) | בינוני | Rate Limit לפי IP, הגבלת אורך, תקרת הוצאה ב-API |
| דליפת מפתח API | גבוה | מפתח בשרת בלבד, לא בקליינט ולא בלוגים |
| XSS דרך תשובות | בינוני | רינדור כטקסט/Markdown מסונן, CSP |
| התחזות לגוף רשמי | בינוני | הרשאה רשמית לשם וללוגו לפני פרסום ❓ |

### פרטיות (Data Map ראשוני)
| מידע | מטרה | אחסון | שמירה | צד שלישי |
|---|---|---|---|---|
| תוכן ההודעות | מתן תשובה | לא נשמר בשרת שלנו | — | Anthropic (עיבוד) |
| כתובת IP | Rate Limit | זיכרון/Edge זמני | דקות | ספק האירוח |

- הודעה למשתמש: "אל תכתבו פרטים אישיים או רפואיים". אין אנליטיקה ואין עוגיות לא-חיוניות ב-MVP ⇒ אין צורך בבאנר הסכמה בשלב זה.
- **דורש בדיקה משפטית:** חוק הגנת הפרטיות ותיקון 13, העברת מידע לספק AI בחו"ל, DPA מול Anthropic, ומדיניות הטכניון לשימוש בכלי AI.

### נגישות
- יעד: WCAG 2.1 AA ות"י 5568 (ללא הצהרת עמידה מלאה בלי בדיקה מקצועית).
- RTL מלא, HTML סמנטי, ניווט מקלדת, focus נראה, `aria-live` לתשובות חדשות, ניגודיות, זום 200%, `prefers-reduced-motion`.
- טיוטת הצהרת נגישות ב-Footer.

## 11. שאלות פתוחות

1. **היכן בטי תחיה?** אב-טיפוס בתוך Claude בלבד, או אפליקציית Web עצמאית להטמעה באתר?
2. **מקור הידע:** האם יש נהלים רשמיים של היחידה שאפשר לספק (PDF/Word/קישורים)? בלי זה בטי תענה מידע כללי בלבד — לא מומלץ לבטיחות.
3. **הרשאה:** האם אתה פועל מטעם יחידת הבטיחות בטכניון ומורשה להשתמש בשם ובלוגו?
4. **קהל ושפות:** מי המשתמשים, והאם נדרשות גם אנגלית/ערבית?
5. **פרטי חירום:** אילו מספרי טלפון ואנשי קשר להציג בכרטיס החירום?

## 12. סיכונים ונושאים לבדיקה מקצועית

- אחריות על עצות בטיחות ← ניסוח הבהרה ואישור ממונה בטיחות ויועץ משפטי.
- פרטיות והעברת מידע לחו"ל ← בדיקה משפטית / ממונה פרטיות.
- נגישות ← בדיקת יועץ נגישות לפני פרסום.
- תמונת הדמות נוצרה ב-AI ← לוודא תנאי שימוש של המחולל ולשקול גילוי נאות.
